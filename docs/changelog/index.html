What's new

Every Orca release, newest first. Orca updates itself, so you get these as they ship.

v0.69.0October 30, 2026

#Orca's VM (macOS)

  • Repair no longer hangs: Repair stopped the VM with a command that waits forever when Lima thinks the VM runs but its host agent is gone. It now stops the VM properly for up to a minute, then by force.
  • One start at a time: when the VM didn't come up (after the Mac ran out of space, say), Orca's own recovery and a reconnect from the app could start and stop it at the same moment, and leave it broken. Now only one of them works on the VM at a time, and Repair or Rescue takes over from Orca's recovery at once.
  • A boot underway is left to finish: when Orca restarts while its VM is booting, it waits for that boot instead of stopping it.

#Gateway

  • Expose via gateway: the dialog shows the new route's address as a link with an Open button, and the container's page stays on it. From the Containers list, the address uses the gateway's domain instead of always .localhost.

#Charts

  • While the window is hidden Orca reads stats and health slowly instead of not at all, and the charts place readings by time, with a gap where the Mac slept. The high-CPU alert counts 10 seconds above 90 %, not three readings.

v0.68.0October 27, 2026

#When Orca's VM doesn't come up (macOS)

  • Rescue: when the VM runs but Linux in it never starts, System Health says so and offers Rescue. Rescue copies the VM's disk first (instantly, as an APFS clone), checks and repairs its filesystems, then starts the VM and the containers that were running. Your containers, images and volumes stay.
  • It shouldn't happen twice: Orca now sets up its VM to repair its own disk at boot, instead of stopping at a disk check nobody can see. That is what kept the VM from starting after its disk had errors.
  • The VM's console in Orca: System Health shows what the VM prints while it boots, live.
  • Ask Claude Code or Codex: Orca writes what it knows to a folder (its logs, the VM's logs, config and console, what runs, free space) and opens the tool there with a first prompt. The prompt says to ask before changing anything, and never to delete the VM.
  • Containers come back: if the VM stopped abruptly (it crashed, or the Mac lost power), Orca starts the containers that were running when it starts the VM again.
  • Low disk warning: the VM's disk grows as it's used, and fails when the Mac runs out of space. System Health warns when less than 15 GB is free.

#Starting Orca

  • No more "failed to start" while the VM boots: the daemon answers right away, and System Health says the engine is starting until the VM is up.
  • Port 9477 in use: the connection screen names the program that holds it and offers to quit it. An older Orca daemon that holds it without answering is quit by itself.

v0.67.0October 26, 2026

#Join a workspace with the address from your browser

The repository's web address now works for joining a workspace, as well as its git URL. Paste https://git.acme.dev/devops/dev-workspace straight from the browser (even a branch or file page in it), or just git.acme.dev/devops/dev-workspace. Orca tries the repository's SSH address first, then HTTPS, and clones the one you have access to. This works on the Workspace page, with orca workspace join and in orca:// links.

#Also

  • Ports, tidied: a run of consecutive ports, such as a TURN server's 41 relay ports, shows as one range, like 49160–49200. The Containers list shows at most four ports per container, with the rest behind +N more. On a container's page, port mappings fill the width in a grid instead of one long column.
  • The update dialog: wider, with the release notes formatted instead of shown as raw text.
  • A broken workspace file: Update now picks up a fix right away and shows its progress, instead of seeming to do nothing.

v0.66.0October 26, 2026

#Orca runs its own engine, everywhere

Orca no longer uses Docker Desktop's engine, on any platform:

  • macOS: Docker runs in Orca's own VM. To use OrbStack, Colima or another engine instead, pick it in Settings → General → Engine. If you used one of those with Orca before, Orca keeps using it.
  • Windows: Docker runs in a WSL distro of Orca's own, orca, made from Ubuntu 26.04. It's reached only by Orca, over an encrypted connection. Your own distros aren't changed.
  • Linux: this computer's Docker or Podman.

What's in Docker Desktop stays there until you bring it over. On System Health, Orca offers to copy Docker Desktop's images, volumes and compose projects into its engine, once. Each volume is read back and checked, and Docker Desktop's own data is only read. Or start fresh: projects are created again on their next start. See Moving from Docker Desktop.

#Windows

  • Setup: System Health sets up Orca's engine in a few minutes.
  • Earlier Orca's Docker: if an earlier Orca installed Docker in your default WSL distro, System Health offers to bring its images, volumes and projects over too.
  • docker in PowerShell: turn it on in Settings → General → Engine. Windows paths in bind mounts (-v C:\code\app:/app) work, as they did with Docker Desktop.
  • docker in one of your WSL distros: turn that on in the same place. Bind mounts from your home folder there work as before.
  • Dev servers on Windows: containers can reach one that only listens on localhost, through host.docker.internal.
  • Clearer port errors: Orca names ports that another WSL distro holds, and refuses to start Kubernetes while another k3s runs in WSL.
  • Settings → WSL2 resources: saving keeps the rest of your .wslconfig.

#Also

  • macOS: Orca no longer restarts its VM on start to re-add a port-forwarding rule it already has. When it does restart the VM for a real config change, it starts your running containers again afterwards.
  • System Health: the setup and repair log opens at its full size.
  • The update dialog: it shows what's new, like this.

v0.65.0October 25, 2026

#Percona Server, as its own engine

engine: percona joins mysql, mariadb and postgres in requires:. A project gets exactly the engine it names, so a team that runs Percona in production can ask for it, and one that wants MySQL proper gets MySQL:

requires:
  database:
    engine: percona
    version: "8.0"
  • Workspace servers: a workspace's shared Percona server is engine: percona too.
  • Run by Orca: with no Percona server around, Orca runs Percona 8.4 or 8.0 itself, from percona/percona-server.
  • Recognised by image: Percona images are recognised as Percona everywhere, also from your own registry or proxy.
  • Imports: from MariaDB, the copy is translated for Percona as for MySQL.

#Stopped apps keep their place

A project's routes, from its orca.yaml or its container labels, now stay while its containers exist, running or stopped. They used to go when the container stopped.

  • On the start page, a stopped app's card stays, greyed out.
  • Its address shows Orca's page saying it isn't running, with Start in Orca, instead of a browser connection error.

#Also

  • Start page: projects in the same group share one section on every environment tab, instead of one section each.
  • Windows:
    • A database's seed command runs with cmd, as workspace setup commands do.
    • Orca no longer garbles the first entry of your PATH when it runs docker and compose.
  • orca-desktop.com:
    • Searching the docs puts the page about what you typed first: "workspaces", "stack", "databases".
    • The homepage has a section on shared databases, and every screenshot shows the current app.
  • App Catalog: pgAdmin's notes cover Docker on Linux, and ClickHouse's mention its CPU requirement.

v0.64.1October 25, 2026

#Editors and terminals render again

The YAML editors (a stack's Compose file and orca.yaml tabs, and the templates' editor) showed line numbers but no text in the desktop app.

The cause was the app's security policy. It blocked the styles the editor adds while it runs, although the policy is written to allow them. The terminal adds its styles the same way, so this likely also fixes:

  • its invisible cursor on macOS;
  • font size changes that didn't apply.

#Find your way around projects

  • Workspace page:
    • A project's name (with ›) opens it: its stack page once it has containers, running or not, and before that, its folder's services, profiles and orca.yaml.
    • Check this machine says what it checks while it runs, and that it only looks.
    • The page's buttons have icons.
  • Open a folder in your editor, terminal or file manager from small icon buttons with a tooltip:
    • on workspace projects;
    • on each stack on the Containers page;
    • on the Workspace page and stack page headers.
  • Gateway page: its status is one row under the title, on every tab: running, domain, certificate, ports and routes.

#App Catalog, October 2026

  • Current versions:
    • PostgreSQL 18;
    • MySQL 9.7 LTS;
    • MariaDB 12.3 LTS;
    • Redis 8, MongoDB 8 and Valkey 9;
    • RabbitMQ 4 and Elasticsearch 9.4.
  • MinIO no longer publishes images, and its Docker Hub images were removed in September; the catalog now uses Chainguard's free build.
  • Mailpit replaces MailHog, which is no longer maintained.
  • New: RustFS, Keycloak, Temporal dev server, ClickHouse, Apache Kafka, Jaeger, Qdrant and pgAdmin.

v0.64.0October 25, 2026

#Start, stop and look into apps from the landing page

  • Details when you want them. The ⋯ beside a project's name on the gateway's landing page opens:

    • Start, Stop and Open in Orca;
    • the project's database;
    • each of its services with the address other containers reach it at and its port on your computer (click to copy).

    Orca Desktop does the starting and stopping, and asks before it stops anything, so no website can do it behind your back. With Show container and port switched off, addresses stay off the page.

  • Apps that aren't running. Their cards are greyed out. Opening one shows a page saying so, with Start in Orca, which opens the app by itself once it answers, instead of an empty 502.

  • Environments in the top bar. The Local / Staging / Production switch is now a compact control next to the layout buttons, ordered from development to production. A link shows only on the tabs it has an address for.

  • Environment links in the workspace. A workspace project can list its addresses in other environments under links:, so the whole team gets DevTest, Test, Stage and Prod tabs.

#Shared databases, hardened

  • docker compose up in a terminal (or a just up / make up) now leaves out the database container a shared server replaces, and reaches the server: Orca points COMPOSE_FILE in .env at its override and puts the project's services on the servers' network, orca-databases.

  • Import brings everything along:

    • stored routines and triggers, without the original DEFINER, which doesn't exist on the new server;
    • with privileges: [create], the project's own <name>_… databases, such as one per tenant.

    It stops before changing anything if it can't take a snapshot first or can't read the source.

  • Reset also drops a project's own <name>_… databases. Restore takes a snapshot of what's there first.

  • Going back to a project's own database (database: own, or removing requires:) puts back the .env values Orca replaced, and its own database container starts again.

  • Stopping the replaced container. When a project moves onto a shared server, its own database container still running from before is stopped; its data stays in its volume for the import.

  • Safer defaults:

    • Two projects can no longer end up sharing a database: the Databases page and the start both say which project has the name.
    • Each project's user is named after its database's name:.
    • On PostgreSQL, one project's user can no longer connect to another's database.
    • Reset, restore and import only touch databases Orca made.

  • Other fixes:

    • Snapshots work on Debian- and Ubuntu-based images such as postgres and mariadb.
    • depends_on conditions such as service_healthy are kept.
    • Services behind a profile get the override too.
    • Windows line endings and file permissions in .env are kept.
    • Long imports and restores no longer time out in the app.

  • Percona Server works as engine: mysql.

#Workspaces

  • Update recovers from a broken or newer workspace file once a fixed one is pushed, and Leave stays available while the file has a problem.
  • A folder already where a project would be cloned is used only when it's a checkout of that project's repo.
  • New and changed routes reach the running gateway right after a join or an update.
  • A logo that can't be loaded no longer stops the rest of the workspace from applying.
  • Icon, logo and certificate paths can't point outside the workspace folder.
  • Clearer errors for links:, project folders and workspace names.

#AI tools

  • Secrets in tool results, such as container environments and passwords in URLs, are now blanked out over MCP too, as they already were for the built-in assistant.
  • The built-in assistant no longer joins workspaces or sets up projects by itself.

#Also

  • Gateway icons after an update. The landing page's icons went missing after updating Orca while the gateway was running. The gateway now gets the new version's settings when Orca starts.
  • Database summaries. The database summaries on the Workspace page, the dashboard and stack pages showed nothing; fixed.
  • Dialogs. The Edit route and Setup guide dialogs had no background.
  • Smaller fixes:
    • deleting a snapshot asks first;
    • Escape closes only the topmost dialog;
    • the Requests tab keeps the row you opened;
    • My links keeps what you typed when saving fails.

v0.63.0October 24, 2026

#AI tools that understand Orca

AI tools connected to Orca now get a map of how it works (stacks, orca.yaml, workspaces, the gateway, databases, worktrees), and can read Orca's whole documentation through a new orca_docs tool. The docs are built into Orca, so they always match the version you run, and need no web access. Before an AI tool writes orca.yaml or orca-workspace.yaml, it's told to read the relevant page instead of guessing keys.

#Move projects onto shared databases

The Databases page now lists every project's own database container. Once a project requires its database on a shared server, its row offers Import into …, which copies the data over:

  • Orca takes a snapshot of the new database first, so you can go back.
  • A stopped container is started for the copy and stopped again.
  • The copy streams from one container straight into the other.
  • Between MariaDB and MySQL, the dump is translated on the way: collations, and the first line of MariaDB's dumps that MySQL rejects.
  • Containers with a random admin password are read with the app's own user.

AI tools get the same with find_database_services and database_import. So you can now ask:

Consolidate our apps' databases into shared databases defined in the workspace, and move their data over.

In our test, Claude:

  1. read the docs;
  2. took stock of every app's database;
  3. noticed a WordPress site ran MariaDB while the team wanted MySQL, and asked;
  4. added the shared servers to the workspace;
  5. wrote requires: for each app;
  6. copied the data over;
  7. compared rows on both sides, and checked that the apps still worked.

#Also

  • Update on the Workspace page no longer fails when the workspace's repo can't be pulled (your own commits, or offline). It says so and applies the workspace as it is in its folder, including your local edits.

v0.62.0October 24, 2026

#Databases

A project can now say in its orca.yaml which database it needs, and Orca provides it:

requires:
  database:
    engine: mysql
    version: ">=8.0"
    replaces: db

Orca gives the project a database and a user of its own, with a generated password, and writes the connection into its .env. The database comes from:

  1. your team's shared server, when the workspace has one for that engine and version;
  2. the project's own database service, when it has one and the workspace doesn't (as without Orca);
  3. a server Orca runs itself: MySQL, MariaDB or PostgreSQL, one per version, started the first time a project needs it.

With replaces:, the project's own database container doesn't start, and the connection is set on the services that used it, even when their compose file hardcodes it. Once a database exists, it stays on its server, so adding a shared server later never leaves data behind.

#Shared servers for a team

A workspace shares servers with a databases: section naming services in its shared compose file. Each project gets its own database and user there, instead of every developer running a database container per project. The workspace file can choose per project with database: mysql or database: own.

#The Databases page

A new Databases page shows every server and the databases on it, which project each is for, its user and size, and what each project requires (or why it can't be provided). For each database:

  • Connect: host, port, user and password, and a URL for TablePlus, DBeaver or DataGrip.
  • Snapshot and Restore: compressed SQL dumps on your computer, with a label such as before-migration.
  • Reset: empty it and run the project's seed command.

A project's database also shows on its stack page, on its card on the Workspace page and on the dashboard. Setting up a workspace project creates its database before the setup command runs, so migrations find it.

#For AI tools

list_databases, database_connection, database_snapshot, database_restore and database_reset. Passwords never reach the AI tool, and restoring or resetting needs your approval. Ask "snapshot onecrm's database, then run the migration", and "restore it" if it goes wrong.

See Databases for everything.

v0.61.0October 24, 2026

#See every request

A new Requests tab on the Gateway page lists requests through the gateway as they happen: time, status, address, route, how long it took and how large the answer was. Filter it by hostname, path, project or status, or keep Only problems.

A failed request says why, in plain words: "Nothing on the gateway's networks answers to crm-app: its container isn't running", or "crm-app runs but doesn't accept connections on that port: it's still starting". Click it for the gateway's own error.

#Check this machine

Check this machine on the Workspace page checks everything a computer needs for the workspace, and says what to do about each problem:

  • the gateway on ports 80 and 443;
  • the domain pointing at this computer;
  • the team certificate's expiry;
  • Orca's certificate authority being trusted;
  • the shared network;
  • registry logins;
  • the secret manager's CLI;
  • access to every project's repository.

#No surprise certificate expiry

When a workspace's certificate is within 30 days of expiring, the Workspace page, the Gateway page and the gateway's start page say so, in yellow, then red once it has expired.

#Group a product's projects

A workspace project can name its group, such as group: oneWebshop for its backend, frontend and admin. They then show together on the start page, the Gateway page, the dashboard and the Workspace page.

#More for AI tools

  • gateway_requests: recent requests and why the failed ones failed.
  • join_workspace: join a workspace from scratch. Your AI tool asks you first.
  • check_workspace: the same check as the Workspace page.
  • fetch_project_secrets: fill in a project's secrets with your own Passbolt or 1Password CLI; the values never reach the AI tool.
  • identify_ports: what each port of a container is.
  • gateway_routes now also says whether each route's service runs.

#Also

  • The start page loads much less: icons are separate files the browser keeps, instead of being embedded in a page that refreshes every 20 seconds.

v0.60.0October 24, 2026

#A tidier start page

  • Shared services as a strip. A workspace's shared services, such as Mailpit, Grafana and MinIO, come first as a row of small chips with a status dot, instead of rows of full cards.
  • Small projects share a row. A project with one or two services no longer takes a whole row: it sits next to others.
  • Room for the search box. How many services run is now under the title, so the search box gets the space, and everything in the top bar lines up.

#Your own apps next to a workspace

When a workspace brings its own certificate, such as one for *.local.acme.dev, your own routes outside that domain, such as myapp.localhost, keep a certificate from Orca's own certificate authority. Before, they got one your browser didn't trust. Names two levels down, such as api.crm.local.acme.dev, which a wildcard certificate doesn't cover, get one too.

v0.59.0October 24, 2026

#The Gateway page, like the start page

The routes table on Orca's Gateway page now works like the gateway's start page:

  • Grouped by project, with shared services last. Click a group's name to fold it; Orca remembers which ones you folded.
  • Whether each service runs: Running, Stopped or Unhealthy, instead of only whether the route is on. A route you switched off says Paused.

v0.57.0October 24, 2026

#Your team's logo on the start page

A workspace can now put its logo in the gateway start page's top bar, next to its title, and on the Workspace page. Add gateway.logo to the workspace file: an image in the workspace repo, a built-in icon or an https URL. Leaving the workspace puts back the start page's previous title and logo.

#My links

Your own cards at the top of the start page: your sprint board, a staging admin, anything you open every day. Add them on the Gateway page's Landing page tab. They're kept on your computer only.

#Projects you haven't set up yet

The start page now shows a workspace's projects that aren't on your computer yet, as dashed cards marked Not set up. Clicking one opens Orca at that project, ready to set up with one click.

#What changed in the workspace

When Orca pulls new changes to your workspace, the Workspace page lists them: Workspace updated: Add Gravity, Renew the certificate.

#Search the web from the start page

The start page's search box now searches Google when no service matches, without setting it up first. Pick another engine, or turn it off, on the Landing page tab.

#Joining puts things where your code is

When you join a workspace, Orca suggests the folder where your git checkouts already are, such as ~/projects, and shows where the workspace and its projects will go. If you already have a copy of the workspace there, Orca joins it where it is.

#Worktrees

The Projects page is now called Worktrees, so it's no longer confused with a workspace's projects. Its page is much more compact: your repositories are listed right away. Paths starting with ~/ now work when you add one.

#Less to read

Pages say what they're for in one line, with a How it works link to the docs, instead of paragraphs of explanation. This covers the Gateway, Kubernetes, Settings, container and stack pages, the worktree setup wizard and more.

#Also

  • The note about switching from Docker Desktop now says correctly that containers and images aren't copied over.

v0.56.0October 23, 2026

#Ports that say what they are

The Gateway page's Suggested routes now tell you what each port is:

  • Names: :8123 ClickHouse HTTP, :5432 PostgreSQL, :3478 STUN/TURN, worked out from the image and the port number.
  • Web or not: a blue dot marks a web page the gateway can serve, a hollow dot anything else.
  • Port runs: a run of ports, like a TURN server's relay range, is one label (:49160–49200 relay ports) instead of forty.

Check asks a container's ports directly. It names a web page by its title, and anything else by its protocol: PostgreSQL, Redis, SMTP, SSH, MySQL and more. It only runs when you click it.

Databases and other containers with no web pages no longer show up as routes to add. They're listed under Other services, with the address to reach them on your computer, such as localhost:5432. Add to Gateway now picks the container's web port.

#A sturdier gateway start

If something else on your computer is using port 2019, such as another Orca's gateway, Orca no longer sends your gateway's settings to it by mistake. It now says what's wrong and how to fix it. Starting the gateway also no longer fails when a just-created certificate takes a moment to appear.

#Also

  • Containers with many ports no longer push their port labels out of the suggestion card.
