## After Docker Desktop is uninstalled, and apt on Linux

- **macOS, when the `docker` command is gone:** Docker Desktop's uninstaller removes the `docker` command Orca had been using. System Health then called Orca's own engine unreachable, and Repair failed and pointed to Recreate VM, although the engine ran fine. System Health, Repair, Rescue and Update Docker Engine now ask the engine itself and don't need the command.
- **A Docker CLI check:** when the `docker` command, `docker compose`, `docker buildx` or the `lima-orca` context is missing, System Health says so. **Set up** installs what's missing with Homebrew and points the context at Orca's engine. The VM, containers and images aren't touched.
- **Setup next to Docker Desktop:** setup installs Homebrew's `docker`, compose and buildx also when Docker Desktop's are there, so they stay when Docker Desktop goes.
- **Linux, apt:** Orca Desktop is in Orca's apt repository. `sudo apt install orca-desktop` installs it, and it updates with the rest of your system; the install page has the two commands. The package needs Ubuntu 24.04 or Debian 13, or newer.
